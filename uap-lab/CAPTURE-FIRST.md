# Capture-first pipeline — 2026-10-29

The operator explicitly authorized provisional motion capture, superseding the earlier model-only capture restriction. Provisional motion is not an anomalous event and must never be presented as one.

NativeFrames reads every completed capture segment and joins decoded frames to original sequence/PTS sidecars. A bounded blocking decoder queue does not replace/drop frames. Missing sequences, timestamp errors, latency and backlog are reported in `/api/live/status` under `native_analysis`; persisted status is `live/native-analysis.json`. Captured and analyzed counts have different starting offsets; compare `generation_first_sequence` through `last_sequence` and measured deltas. `model_classified_frames=0` explicitly distinguishes this stage from model classification.

NativeMotion analyzes each native 1920×1080 frame for temporal change with compact spatial detail. There is no frame sampling and no candidate limit in analysis. Notification summaries include up to 128 boxes with the full candidate count; complete source video remains available. A single-frame candidate can trigger provisional evidence; the background requires one initial frame and resets after timestamp discontinuities. Diffuse/global changes are marked unclassified rather than assumed anomalous or negative.

ProvisionalCapture uses the existing lossless rolling buffer, 10-second pre/post-roll, native timestamps and both RF logs. Retention adds eight seconds of analysis margin. Extended motion creates at most 60-second clips, with overlapping pre-roll in subsequent clips. Manual recording can take over an active provisional clip. Storage reserve and explicit pre-roll completeness remain enforced. No synthetic frames are introduced.

`provisional.json` and `provisional-candidates.jsonl` persist alongside each session. The local queue imports completed clips by SHA and submits only one heavy evaluation at a time through the existing M6 worker. Existing M6 locking/nice priority remains unchanged. Dispatcher leases survive web restarts; recovery checks remote job identity before submitting. Transfers can retry without classifying a failure as a negative. Labels, omitted/reviewed history and saved models are untouched.

The Recent events page exposes provisional video/status and the Label videos motion-collection source supports review. Results with or without model matches require review. Automatic deletion is intentionally disabled because held-out classification accuracy is not established. Local originals remain available offline and the existing Internet Archive workflow remains enabled.

Important limitations: live appearance tags still use the older rotating model matcher. This deployment fixes capture-before-classification, not reliable real-time semantic identification. The proposed fast descriptor classifier failed initial re-identification checks and is NOT deployed. Model-bank throughput/accuracy, true held-out anomaly performance and temporal model training remain open. Current saved temporal model has no linked training windows. Buffer-segment analysis introduces approximately 1–3 seconds of latency; metrics must be monitored under sustained load. This is not a certification of professional readiness or a claim that every possible faint/subpixel object is detected.
